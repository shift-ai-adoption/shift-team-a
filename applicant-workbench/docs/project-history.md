## 2. 採用した構成

ローカルで完結する画面修正ワークベンチとして、次の構成を採用しました。

| 要素 | 採用内容 |
|---|---|
| 画面 | React 19 + Vite 6 |
| API | Express 5 |
| サンプルデータ | Node.js組み込みSQLite |
| デザイン | Penpot 2.15.4 |
| Penpotデータベース | PostgreSQL 15.13 |
| キャッシュ | Valkey 8.1.3 |
| アセット | MinIO |
| AI連携 | Penpot公式MCP 2.15.4 |
| ブラウザ検証 | Playwright |
| 実行 | Docker Compose |

Penpot本体と公式MCPは同じバージョンに固定しました。MinIOはDocker Hubから取得できなかったため、公式Quayイメージへ切り替えました。公開ポートはすべて`127.0.0.1`に限定し、PostgreSQL、Valkey、MinIOはホストへ直接公開していません。

Codex用MCP設定は`.mcp.json`ではなく、プロジェクトの`.codex/config.toml`に記載しました。OpenAI APIキーをサンプルアプリやPenpotへ設定する構成にはしていません。

## 3. 申請者CRUDサンプルの作成

一般的な公的機関の事務処理システムを想定し、個人・法人が自分自身を申請者として登録・管理するサンプルを作成しました。実在の行政サービスではなく、データはすべて架空です。

実装した画面と機能は次のとおりです。

- 申請者一覧
- 氏名、フリガナ、法人番号、メールアドレスによる検索
- 個人・法人の絞り込み
- 並び替えとページング
- 個人申請者の新規登録
- 法人申請者の新規登録
- 入力内容の確認
- 登録完了
- 詳細表示
- 編集
- 変更履歴
- 削除確認と削除キャンセル
- 必須、フリガナ、郵便番号、メール、電話番号の入力検証
- 法人番号の形式・重複検証
- 更新競合の検出
- 利用者ごとのデータ分離
- PC表示とスマートフォン表示

デモ利用者として、架空プロフィール3件を持つ「山田 太郎」と、空状態から試せる「佐藤 花子」を用意しました。この切り替えは開発用であり、本人認証ではありません。

サンプルは次のURLで操作できるようにしました。

- 申請者管理サンプル: http://localhost:3200/
- Penpot: http://localhost:9001/
- Penpot公式MCP: http://localhost:4401/mcp
- Vite画面修正プレビュー: http://localhost:3201/

## 6. サンプル操作・ログインの案内

ユーザーから次の質問を受けました。

> サンプルを操作したいです。どうしたらいいですか？

申請者管理サンプルは`http://localhost:3200/`からログインなしで操作できること、新規登録、確認、詳細、編集、削除を試せること、右上でデモ利用者を切り替えられることを案内しました。

次に、Penpotのログインについて質問を受けました。

> ログインはどうしたらいいですか？

ダッシュボードが表示されている場合はログイン済みであること、ログイン画面が出た場合は構築時に作成したローカルアカウントを使用することを案内しました。メールアドレスは案内しましたが、パスワードは本文へ記載せず、Git管理外の`data/penpot-local.json`を参照する形にしました。

修正対象を「Penpotのデザイン」「動くサンプルアプリ」「両方」のいずれかで指定し、このCodexチャットへ自然文で依頼する方法を案内しました。Penpotの変更だけではReactアプリへ自動反映されないため、両方を変更する場合は明示する必要があることも説明しました。

## 8. Penpot MCP直接編集の有効化

ユーザーから次の依頼を受けました。原文の「軽油」は「経由」の意味として対応しました。

> MCP軽油の直接編集をできるようにしたいです。

Codex側のMCP設定はすでに存在していたため、Penpot側の公式プラグイン導入を進めました。プラグインが要求した権限は次のとおりです。

- デザイン内容の読み取り・書き込み
- ライブラリの読み取り・書き込み
- コメントの読み取り・書き込み

この権限は画面編集より広いため、自動承認レビューが、ユーザーの明示的な同意なしでのインストールを拒否しました。要求権限を説明したうえで確認し、ユーザーから次の回答を受けました。

> 許可してよいです。

承認後、Penpot MCP Pluginをインストールし、権限を許可しました。プラグインを`Connected`にし、MCPからPage 2のレイヤー構造を読み取れることを確認しました。

書き込み確認では、ボード名を一時的に変更して元へ戻しました。途中で利用上限により自動承認レビューを実行できない事象と、専用ブラウザーが閉じてMCP接続が切れる事象がありました。ユーザーから次の指示を受けて再開しました。

> 続行

専用ブラウザーを再起動し、プラグインを再接続した後、読み取りと書き込みの両方に成功しました。プロジェクトルートの`.codex/config.toml`にもPenpot MCP設定を追加しました。

## 9. PenpotとAIの役割の説明

ユーザーから、AIへ指示する場所とAIプロバイダー設定について次の質問を受けました。

> penpotのどこからAIに指示するのですか？
> penpotにAIプロバイダーの設定はしないのですか？
> それともあくまでもAIエージェントからMCP経由で指示するのでしょうか？

今回の構成は次の流れであると説明しました。

```text
ユーザー → Codexチャット → MCP → Penpotデザイン
```

Penpot内にAIへの指示入力欄やAIプロバイダー設定は設けず、Penpot MCP PluginはCodexからの操作を受け取る接続窓口として使用します。
