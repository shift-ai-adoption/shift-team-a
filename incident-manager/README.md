# インシデント管理・開発用モデル

開発では **PostgreSQL = Accessのデータ、Node.jsのWebフォーム = Accessフォーム** として模擬します。本番の保存先はAccessのままです。本番DBをPostgreSQLへ移す提案ではありません。

## 起動

Docker Desktopをユーザーが起動して、Linuxコンテナが使用できる状態にします。Node・PostgreSQL・npmのホストへのインストールは不要です。

このディレクトリで実行します。

```powershell
docker compose up --build -d
docker compose ps
```

ブラウザーで http://localhost:3100 を開きます。「架空サンプル」→「項目を抽出」→入力確認→「登録する」で試せます。

停止は `docker compose stop`。DBは名前付きボリュームに保持します。`docker compose down -v` はデータを消すため、通常の停止には使わないでください。初期DDLは空のDBに対してのみ実行されます。

初回ビルドはコンテナイメージとnpm依存パッケージのダウンロードが必要です。実行時のNodeアプリとDBは内部ネットワークに置き、アプリから外部LLM等へ接続する実装はありません。入口のNginxだけが別ネットワークにも接続し、127.0.0.1:3100で画面を公開します。DBとNodeのホスト向けポートは公開しません。

## 初期版の範囲

- 指定された入力項目による登録・更新・検索・論理削除、内容コピー。
- メール本文の定型抽出。日時のタイムゾーン指定がなければ日本時間として扱い、確認メッセージを表示。
- 発生日時・内容が同じ場合も自動除外しない。日時違いの再発も別件登録。新規／既出は人が選択。
- 同じ登録要求の通信再試行だけ二重書込みを抑止。
- FAQでは原因を保存しない。
- 受付から初回回答までの経過分数（秒以下は切捨て）。営業時間・休日補正なし。
- 更新版数を照合し、別画面の更新を上書きしない。
- 検索結果と連動した件数・平均一次回答時間・軸別集計。
- Access入力項目を想定したExcel出力。ブラウザーからダウンロード（固定共有フォルダーへの自動保存は未実装）。
- テンプレートによる報告メール文章案、編集・保存・コピー。メール送信や初回回答日時の自動更新はしない。
- 外部送信許可とLLMログ入力許可の保存・履歴。初期値は両方false。設定をオンにしてもLLM未接続のため通信しない。

## 未実装・本番で検証する部分

- Access実接続、既存フォームの改修、Access側からの更新との競合処理。
- Outlook classicの自動取得（本番は会社メール、ログオン中にWindows連携処理を実行する想定）。開発版は本文貼付で模擬。
- LLMによるサマリ・原因妥当性評価・調査提案。内部LLMなし・外部禁止のため初期版では利用不可。
- 認証・ユーザー別権限・操作者の本人確認・本番向け監査。開発版の履歴は操作内容と時刻のみ。
- 3,000件の実データ移行、共有フォルダーへの定期出力、削除データの復元画面、バックアップ運用。

外部公開・LAN公開用の構成ではありません。5名・同時2名向けの本番運用は、認証・権限とAccess連携の実機検証を別途行います。

## テスト（すべてコンテナ内）

```powershell
docker compose exec web npm test
docker compose exec -e RUN_INTEGRATION=1 web npm test
```

通常のテストは抽出、日時、FAQ、入力チェック、報告テンプレートを検証します。統合テストは起動中のAPI・DBを使い、再送、再発登録、競合、下書き、設定、Excelの文字列保持を検証します。架空レコードを作り、終了時に論理削除します（履歴には残ります）。設定は元に戻します。検証専用DBで実行してください。

## ファイル

- `db/001-schema.sql`: 開発用仮モデル。
- `src/domain.js`: 入力ルール・本文抽出・文章テンプレート。
- `src/repository.js`: PostgreSQL固有の保存処理。本番Access移植時の境界。
- `src/server.js`: Web API・Excel出力。
- `public/`: 模擬フォームと管理画面。
- `docs/access-handoff.md`: 本番Accessへの対応方針と段階計画。

Docker Desktopの無料利用可否は所属組織の条件に依存します。アプリの依存ソフトはOSSですが、本番では既存Officeライセンスを使用します。
